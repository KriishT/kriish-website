## The problem

Security and compliance reviews (PCI DSS, SOC 2, DORA) ask for diagrams of how a system is put together and where regulated data moves. Teams draw them by hand, and they are out of date almost immediately. Trailmap draws them from the code instead.

## Where it stands

Trailmap is still being built. I started it in April 2026 and I’m still working on it. There’s no hosted version yet, but the whole product runs on a laptop with no accounts: an embedded database and a mocked GitHub stand in for the real ones.

## My role

I’m building it on my own, from the design to the scanner to the web app.

## What it does

- **Three sheets.** System architecture, data flow, and network exposure, drawn on survey-sheet paper with a title block that carries the commit, the date and a hash of the data.
- **Evidence behind every line.** Select any box or arrow and you see the code that proves it.
- **Drift checks on pull requests.** A check and one comment on each pull request say when a change adds a vendor, exposes a datastore or moves regulated data across a scope boundary.
- **Revisions and export.** Every scan is a revision (Rev A, B, C), and a sheet exports as PDF, SVG, JSON or CSV.
- **Where you already work.** A command line, a GitHub Action and an MCP server for coding agents.

## Decisions and tradeoffs

### Show the evidence, and how sure it is

A diagram you can’t check is just a claim. So every connection links to the code it was inferred from, and the line style shows how confident the scanner is: solid, dashed or dotted. A question mark means “possible, not confirmed in code”.

### Support an assessment, don’t certify anything

Trailmap makes no claim that anyone is compliant. The notes in every export say what a person still has to verify, because code can’t show who has access or whether a policy is followed.

### Run locally first

The scanner runs on your machine, and nothing is uploaded unless you ask for it. That keeps a codebase’s architecture private until its owner chooses to share it.

## What’s next

The scanner can’t resolve everything: URLs built at runtime, service discovery through a registry and generated code stay out of reach. Those connections show up dashed or dotted, so a person can confirm, hide or add them. Making that review fast is the next thing to get right.
